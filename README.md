# Fishcheckbot — учёт переработки рыбы в ресторанной сети

Telegram-бот, который заменил бумажные акты разбора рыбы в ресторанной сети: сотрудник вводит четыре веса, бот считает отходы, сверяет их с нормативами, сохраняет акт и отправляет сводку в рабочий чат управляющих. Работал в продакшене в нескольких городах.

Небольшой, но «взрослый» B2B-проект: строгий TypeScript, Repository Pattern, чистые функции бизнес-логики, Zod-валидация конфигурации, структурное логирование, Docker и CI.

## Возможности

- **Акт разбора по шагам.** Тип рыбы кнопкой → вес филе по этикетке → слайсы и суши → красная обрезь → чёрная обрезь. Бот проверяет каждое значение в контексте предыдущих, считает вес отходов и отклонения от нормативов, показывает итог перед отправкой.
- **Роли.** Кандидат проходит регистрацию (город и ресторан) и ждёт одобрения; сотрудник заполняет акты; администратор одобряет заявки, управляет сотрудниками и параметрами видов рыбы.
- **Мультигород.** Сотрудник привязан к городу и ресторану; сводка каждого акта уходит в рабочий чат с отметкой «в норме» или «отклонения». Сбой отправки сводки не отменяет сохранённый акт.
- **Справочник ресторанов** сейчас задан в коде; конфиг предусматривает подключение Google Sheets (необязательные переменные `GOOGLE_SHEETS_*`).

## Архитектурные решения

- **Чистые функции для бизнес-логики.** `services/act/calculator.ts` и `validator.ts` без побочных эффектов: тестируются без базы и Telegram и переиспользуются в любом интерфейсе.
- **Repository Pattern.** Работа с MongoDB изолирована в `services/mongodb/repositories`, хендлеры бота её не видят — репозитории легко подменить в тестах.
- **Форма как конечный автомат.** Состояние заполнения акта и регистрации хранится в `user.temp`; шаги акта описаны явными типами.
- **Конфигурация через Zod.** Переменные окружения проверяются при старте: бот не запустится с неполным конфигом.
- **Надёжность.** Структурное логирование (Winston) с ротацией, корректная остановка по SIGTERM и SIGINT с закрытием соединений.

## Безопасность

- Все секреты — в переменных окружения, в репозитории только шаблон `.env.example`.
- Доступ по ролям проверяется на уровне middleware.
- Контейнер запускается от непривилегированного пользователя (UID 1001).

## Стек

Node.js 20, TypeScript, Telegraf, MongoDB + Mongoose, Zod, Winston, Vitest, ESLint (typescript-eslint), Docker, GitHub Actions. Около 1 200 строк кода и 18 юнит-тестов на расчёты и валидацию.

## Структура

```
src/
  bot/
    index.ts            точка входа, подключение хендлеров и middleware
    middleware/         проверка ролей, логирование входящих
    handlers/           /start, регистрация, акт (конечные автоматы), администрирование
    keyboards/          динамические клавиатуры по роли
  services/
    act/                calculator.ts, validator.ts, formatter.ts — чистые функции
    mongodb/            подключение и репозитории User, Act
  models/               Mongoose-схемы и типы
  config/               нормативы, константы, Zod-валидация окружения
  utils/                логгер, ошибки, помощники
tests/unit/             calculator.test.ts, validator.test.ts
docker/                 Dockerfile (non-root), docker-compose.yml с MongoDB
```

## Запуск

```bash
pnpm install
cp .env.example .env        # BOT_TOKEN, MONGO_URI, ADMIN_TELEGRAM_ID, TARGET_CHAT_ID
pnpm dev                    # бот с перезапуском при изменениях (нужны BOT_TOKEN, ADMIN_TELEGRAM_ID, TARGET_CHAT_ID)
pnpm test                   # юнит-тесты
pnpm typecheck && pnpm lint
```

В Docker вместе с MongoDB:

```bash
docker compose -f docker/docker-compose.yml up -d --build
```
